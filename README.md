# Xray Manager

基于 [Wails v3](https://wails.io/) + [Vue 3](https://vuejs.org/) 开发的代理规则可视化管理工具，底层由 [sing-box](https://github.com/SagerNet/sing-box) 驱动，提供简洁易用的图形界面来管理代理节点。

支持 Windows、macOS、Linux 三平台。

## 功能特性

**代理协议**
- 支持 Shadowsocks、VMess、VLESS、Trojan、HTTP、SOCKS 协议
- 支持 Hysteria2、TUIC v5 协议
- 支持 TCP、WebSocket、gRPC、HTTP/2 传输协议
- 支持 TLS / Reality 传输层安全配置

**规则管理**
- 添加、编辑、删除代理规则，支持拖拽排序
- 批量编辑：多选节点后统一编辑，每个节点一张可折叠卡片
- 导入/导出规则为 JSON 文件（仅导出选中节点及其关联的分组/故障转移/链式代理）
- **前置代理**：客户端内节点经指定前置节点出站，用于中转加速（设置 → 前置代理）。
  可限定只对选中的分组生效，并单独排除个别节点（例如必须从本机 IP 出去的节点）
- **检查更新 / 自动更新**：从 GitHub Releases 检测新版本，支持手动与启动时自动更新
- **多选 Delete 快捷键**：选中节点后按 Delete 删除（弹窗确认）
- 解析分享链接（vmess://、vless://、ss://、trojan://、http(s)://、socks://、socks5://、hysteria2://、hy2://、tuic://）；
  暂不支持 `hysteria://`（Hysteria v1，与 hysteria2 是两套互不兼容的协议）
- 批量导入分享链接为批量预分配 ID 与端口，几十上百条粘贴导入约 0.5 秒完成
- 选中普通节点后按 Ctrl+C 可复制标准分享链接，支持粘贴到 v2rayN 等其他客户端；Ctrl+V 可从其他客户端复制的分享链接直接导入
- Hysteria2 支持 pinSHA256（证书指纹，自动开启跳过证书验证）与端口跳跃（mport）
- 多选：Shift 连选、Ctrl 点选，配合批量启停 / 删除 / 编辑 / 分组
- 批量选择、启动、停止、删除（批量操作在后端并发执行，上千节点也能秒级完成）
- 列表虚拟滚动，上万节点仍可流畅滚动与操作
- 列显示可自定义：点表头右侧 **☰** 勾选要显示的列，选择自动保存
- **节点备注**：独立于订阅下发的别名，由你自己填写，订阅更新永不覆盖；可排序、可搜索
- **绑定固定出口 IP**：给节点绑定期望的出口 IP，启动后探测到的真实出口 IP 与它
  不一致就自动停用，适合对端按 IP 做白名单的场景（机场换了落地 IP 后节点仍连得通，
  但请求会被对端拒绝，而你毫无察觉）。留空则以首次探测到的 IP 为准，只有开启绑定的节点参与
- 本地代理统一为混合端口，同一端口同时支持 HTTP 和 SOCKS5，自动分配不重复的本地端口
- 多客户端实例通过操作系统端口占位协调推荐端口，未启动节点也不会与其他实例重复分配；端口冲突时不会终止其他客户端的代理进程
- 启动时端口被其他程序占用会指出是哪个进程（进程名 + PID），并可一键结束后自动重试；
  自身进程与看不到详情的系统进程不提供该选项，避免误杀

**故障转移与链式代理**
- 链式代理：多节点链式串联，流量依次经过各节点转发
- 故障转移：多节点主备切换，主节点故障时自动切换到备用节点
- 二者均支持测速、健康检测、流量监控，可作为系统代理

**动态会话代理（住宅代理多出口 IP）**
- 单个端口按客户端用户名动态切换住宅代理出口 IP，无需为每个会话开一个端口
- 客户端在代理用户名中传入会话标识，按模板（含 `{session}` 占位符）拼成上游真实用户名
- 混合端口：HTTP 与 SOCKS5 客户端均可接入，SOCKS5 侧会话标识取自用户名认证
- 可选前置加速节点（普通节点 / 链式 / 故障转移），用于直连境外网关很慢或不通的情况
- 上游密码保存在本机，客户端只需知道会话标识；可另设客户端密码防止本机其他程序滥用

**节点测速与健康检测**
- 测速：普通节点直连测 TCP 延迟 + 通过代理测下载速度（限时采样，慢速网络不超时）
- 测速 URL 与请求 Header 可在设置中自定义（默认沿用内置浏览器 UA）
- 健康检测：无需启动即可检测普通节点连通性（DNS → TCP → TLS/Reality，QUIC 走 UDP 探测），支持后台定时自动检测
- 状态分级：在线、延迟较高、超时、TLS 失败、DNS 失败、Reality 失败、仅 IPv6
- 并发按节点规模自适应，上万节点约 100 秒完成一轮检测
- 按健康状态筛选与批量选中，可快速挑出失败节点批量删除
- 批量选中重复节点（按协议+地址+端口+凭证+传输层参数判重，忽略别名）与
  重复出口 IP 的节点；只选中不自动删除，每组保留一个（优先保留运行中、
  有出口 IP 绑定或有备注的那个），核对后自行删除

**流量监控**
- 实时上/下行速度
- 今日 / 累计流量统计（跨天自动清零），最近启停时间记录
- 支持手动清零

**订阅管理**
- 支持 Clash YAML、V2Ray JSON、SIP008、Base64 格式
- 添加与编辑订阅（名称、地址、自动更新、更新间隔、更新方式、所属分组）
- 更新方式可选：直连 / 系统代理 / 指定节点（临时建立代理，适合本机无法直连订阅链接的情况）
- 批量导入订阅：粘贴多条链接一次汇入同一分组，订阅名按「分组名-序号」自动编号，
  再次导入会接着编号；单条失败不影响其余
- 自动定时更新，智能节点合并，订阅节点自动关联分组
- 拉取订阅默认伪装成 Shadowrocket 的 User-Agent（机场按 UA 返回不同内容，未知 UA 常只返回网页或精简列表），可在设置中自定义
- 多个订阅可汇入同一分组；节点按别名、协议、地址端口、凭证及传输层参数
  （ws path / SNI 等）识别，重复更新不会累积重复节点
- 机场改名（附上剩余流量、到期日、重排序号）后仍能认出是同一个节点，
  保留它原有的本地端口、备注与出口 IP 绑定，不会删掉重建

**分组管理**
- 手动创建自定义分组
- 订阅自动创建分组，也可让多个订阅共用一个分组
- 多选节点后批量设置分组
- 按分组批量启停节点，分组显示节点计数，支持筛选未分组节点
- 删除分组时级联清理该分组下节点的归属

**HTTP API**
- 可在设置中启用或关闭 HTTP API，并配置监听地址与端口
- 支持可选 Bearer Token 鉴权，非本机监听时强制启用鉴权
- 提供节点、分组、订阅、故障转移、链式代理和动态会话代理的查询、创建、修改、删除与启停接口
- 支持获取全部、已启动、指定分组、指定订阅或指定复合代理的本地 HTTP/SOCKS5 地址
- 内置 OpenAPI 3.0 规范与 Swagger UI 文档

**系统集成**
- 系统代理：一键将节点设为系统代理（Windows/macOS 自动设置，Linux 需手动设置环境变量）
- 系统托盘：最小化到托盘，右键菜单快捷操作（一键启停所有节点、故障转移、链式代理）
- 开机自启：支持设置开机自动启动
- 状态恢复：关闭应用时自动记录已启用的节点，重新打开后自动恢复（包括普通节点、故障转移、链式代理）
- 进程管理：启停时自动清理端口残留进程，避免僵尸进程导致端口占用
- 深色模式：亮色/深色主题切换
- 实时日志：支持搜索、按级别（警告 / 错误等）筛选，鼠标悬停时暂停自动滚动便于查看
- 嵌入式二进制：使用 go:embed 打包 sing-box 内核，开箱即用无需额外安装

### v2.11.0 更新内容

**新增**

- 批量导入订阅：粘贴多条订阅链接，一次全部汇入同一个分组。
  订阅名按「分组名-序号」自动编号（机场合集-1、机场合集-2……），
  往已有订阅的分组里再导入会接着编号而不是从 1 重来；
  `#` 开头的行会被忽略，单条链接失败不影响其余，
  一条都没成功时新建的空分组会被自动清理。
  此前添加订阅一次只能一条，十几个机场就要重复十几遍，且每条默认各建一个分组
- 批量选中重复节点：跨订阅买到同一家落地、或同一机场在不同订阅里重复下发，
  会攒下大量实际等价的节点，而它们的别名往往不同（机场爱加剩余流量和编号），
  肉眼很难挑。判重按协议+地址+端口+凭证+传输层参数，**忽略别名**
- 批量选中出口 IP 重复的节点：不同节点可能共用同一个落地 IP
  （机场超售、同一台服务器挂多个入口），对按 IP 做白名单的用途来说留一个就够。
  只比对运行中且已探到真实 IP 的节点
- 两个去重都是**只选中、不自动删除**：每组保留一个，你核对后自行点「删除」。
  保留优先级为 运行中 > 有出口 IP 绑定 > 有备注 > 列表首位——
  每一档护住的都是重建不回来的东西，被选中待删的是克隆体

**修复**

- 修复批量场景下订阅 ID 可能撞车：订阅 ID 取自纳秒时间戳，而 Windows 的时钟
  粒度是毫秒级，实测紧凑循环里取 50 次得到的是同一个值。多条订阅共用一个 ID 后，
  更新其中一条会把其他几条的节点全部当成「已失效」删掉再重建。
  批量导入改为一次性生成互不相同的 ID

### v2.10.0 更新内容

**新增**

- 启动节点时若本地端口被其他程序占用，会查出占用进程并弹窗询问是否结束它，
  确认后终止进程、等端口真正释放，再自动重试启动。
  此前只报一句「端口已被占用，请更换端口」，既不说是谁占的也没有处理手段，
  而占用方往往是临时借用端口的网盘、音乐客户端之类。
  安全判定放在后端：自身进程一律不可终止，取不到进程名的（多半是权限不足
  看不到的系统进程）同样不给；只终止界面显式点名的进程，不接受
  「结束占用这个端口的一切」——探测与终止之间端口可能易主，照旧快照杀会误伤
- 两条启动路径的报错都带上占用者，例如「端口 11001 已被 CloudMusic.exe (PID:8472) 占用」

**修复**

- 修复端口注册表损坏导致程序完全打不开：桌面上只多出一个空的 xray-configs 目录，
  窗口不出现，控制台留下一句 `invalid character '\x00'`。
  成因是保存注册表时先 WriteFile 再 Remove/Rename，而 WriteFile 只保证数据进了
  页缓存——此时断电会留下长度正确、内容全是 NUL 的文件。
  现在注册表损坏会就地重建（原文件另存为 .corrupted 备查），
  且保存改为写临时文件 + fsync + 原子替换，从源头上不再产生半截文件。
  注册表同步失败也不再阻断启动与配置保存——它只是多实例协调端口用的缓存，
  而此前一旦损坏，连用户的节点都保存不了
- 主配置文件的保存同样改为 fsync + 原子替换：它每次改动都要全量重写，
  节点多时可达数 MB，写入窗口更长，而这份文件丢了就是全部节点、订阅、分组都没了
- 修复取消勾选「启用前置代理」后重启又被打回启用：该字段是普通 bool，
  无法区分「老配置里没有这个字段」和「用户明确关掉了」——两者都是 false，
  而启动时兼容旧配置的迁移会把「选了节点 + 未启用」补成启用，
  于是每次重启都把用户取消的勾选打回去

### v2.9.0 更新内容

**新增**

- 节点备注：与订阅下发的别名相互独立的一个字段，由你自己填写，订阅更新永不覆盖。
  别名归机场所有，每次更新都会被改掉（常带上剩余流量、到期日、重新编号），
  想在节点上记点自己的东西（「这个给爬虫用」「客户 A 专用」）此前无处可放。
  备注列可排序，也可用顶部搜索框直接搜
- 绑定固定出口 IP：给节点绑定一个期望的出口 IP，启动后探测到的真实出口 IP
  与它不一致就自动停用该节点。
  本地端口常被交给外部程序使用（爬虫、浏览器、业务系统），而对端往往按 IP
  做白名单；机场换了落地 IP 后节点仍然连得通，但请求会被对端全部拒绝——
  此时「能连上」反而是最坏的情况，外部程序还在往这个端口发流量，而你毫无察觉。
  绑定后故障会显式暴露而不是静默失败。
  只有显式开启绑定的节点参与检查，其余节点行为完全不变；
  绑定值以首次成功探测到的 IP 为准（你无法在启动前预知机场分配的 IP），
  也可在节点编辑里手填，或点击「绑定IP」列一键绑定/解绑当前 IP
- 探测真实出口 IP 时优先取 IPv4：兜底探测点改用只有 A 记录的域名，
  并对结果做 IPv4 校验，拿到 IPv6 就换下一个探测点。
  双栈出口的节点走双栈探测点时会随机返回 IPv4 或 IPv6，同一个节点两次探测
  拿到不同家族的地址，绑定比对就会把没变的节点误判成「IP 变了」。
  全部探测点都只给 IPv6 时仍然接受，能用的节点不该因为拿不到 IPv4 就被判成不通

**修复**

- 修复订阅更新后备注丢失、本地端口漂移：节点身份标识的第一个字段是别名，
  机场一改名（附上剩余流量、到期日、重排序号）身份就对不上，旧记录被当作
  已失效删除、同一个节点又以新 ID 和新分配的端口重新插入。
  现对第一轮没配上的两侧再按「去掉别名的标识」配一次，认出「只是改了名」的节点，
  保留它原有的 ID、本地端口、备注与出口 IP 绑定。
  只在两侧都唯一时才认——同一 CDN 下若有多个仅靠别名区分的节点，
  贸然按地址配对会把 A 的备注挪到 B 上，此时宁可退回原有的删除+新增
- 修复删除分组后左侧列表出现两个同名分组：分组管理器持有的是配置切片的内部指针，
  而删除分组时切片就地前移，缓存里的指针会串到相邻分组上；之后重命名分组
  （或更新订阅名）就改到了无关分组头上，并被写进配置。
  已写坏的分组名不会自愈，启动时会按订阅名回正一次
  （只处理被单个订阅独占的分组，多订阅共用的分组名和手动分组不受影响）

**调整**

- 节点列表的操作列去掉「检测」与「删除」两个按钮：两者在工具栏都已有批量入口
  （勾选行后点「健康检测」「删除」，未勾选时健康检测作用于全部），
  逐行再放一份既占地方，删除按钮逐行摆着也容易误点

### v2.8.0 更新内容

**新增**

- 启动时检测节点端口与系统动态端口范围是否重叠，重叠时在日志中给出提示与修复命令。
  Windows 的动态端口范围被改低（例如起始值 10000）时，节点端口会落在其中，
  随时可能被其他程序借用为临时源端口，表现为「同一个节点时好时坏、换个端口就正常」。
  这种占用处于 Bound 而非 Listen 状态，netstat 和常见的端口查看工具都看不到，
  此前几乎无法自行定位
- 点击列表中的本地端口即可复制该节点的本地 HTTP 代理地址，
  格式与工具栏的批量复制一致（`http://127.0.0.1:端口`）

**修复**

- 修复分片启动失败时丢失节点级原因：整片节点都被剔除时，日志与界面只显示
  「分片内没有可用节点」这句汇总结论，看不出是哪个节点、哪个端口、为什么。
  现在会附上每个节点各自的原因（端口被占用、配置无效等），
  且单个/批量启动都优先返回节点专属原因而非笼统的调谐错误

### v2.7.0 更新内容

**新增**

- 前置代理支持限定生效范围：可选择多个分组，只有这些分组内的节点经前置节点出站；
  也可单独排除个别节点，让它们直连（适合必须从本机 IP 出去、或经前置反而不通的节点）。
  留空表示对全部节点生效，与此前的全局行为一致，旧配置无需改动
- 前置代理改用独立的启用开关：关闭时保留已选节点与生效范围，
  下次启用不必重新配置（此前只能把节点选成「不使用」，等于清掉配置）
- 链式代理与故障转移也可作为前置代理：它们通过本地端口接入，
  启动受影响的节点时会自动把未启动的前置代理先拉起来
  （否则这些节点都会报「代理连接失败」，而问题其实不在它们身上）。
  例外节点列表同样覆盖这两类
- HTTP API 的 `PUT /api/v1/settings/pre-proxy` 相应支持 `enabled`、`groupIds` 与 `excludedIds`

### v2.6.1 更新内容

**修复**

- 修复批量启动后大部分节点跳过连通性验证、拿不到真实 IP：验证协程会跳过已被
  用户停止的节点，但节点置为「已启用」发生在触发验证之后，先跑起来的协程
  把正在启动的节点误当成已停止。实测上千节点里只有几十个走了验证
- 修复停止节点后仍显示「验证中」、状态灯一直黄色呼吸：批量启动会把整批标记为
  验证中，而探测有并发上限，排队中的节点要等很久才轮到；停止操作没有清除该标记
- 修复验证期间列表不刷新，日志已出真实 IP 但界面计数半天不动：
  刷新用的是防抖，而验证期间事件持续不断，计时器一直等不到空档。
  改为节流（最多每 500ms 刷新一次），后台刷新不再闪烁加载遮罩

**新增**

- 「更多 → 复制本地代理 (HTTP / SOCKS5)」：把节点的本机监听地址按行复制到剪贴板，
  供爬虫等程序直接使用。选中了节点就复制选中的，没选中则复制全部已启用节点
  （验证中的除外，它们连通性尚未确认）

### v2.6.0 更新内容

**重大变更**

- 普通节点改为分片运行：多个节点共享一个 sing-box 进程，不再是一节点一进程。
  实测 1583 个节点从约 50 GB 降到约 210 MB（6 个分片），内存降低约 290 倍，
  上千节点终于能同时启动而不闪退（实测批量启动 1477 个节点，筛出 1426 个可用）。
  每个节点仍监听原有的本地端口，爬虫、健康检查、测速、系统代理的用法完全不变。
  链式代理与故障转移有各自定制的配置，仍是独立进程

- 内核统一为 sing-box，移除 Xray-core。sing-box 支持的协议是 Xray 的超集
  （Hysteria2 / TUIC 只有 sing-box 能运行），且单内核避免了两套配置生成逻辑
  不同步——REALITY 就曾因此在 sing-box 侧被漏写。安装包体积因此减少约 96 MB。
  节点配置无需改动，原有节点全部照常工作
- 内置 sing-box 升级至 1.13.16（原 1.13.14）

**修复**

- 修复 REALITY 节点经 Hysteria2 / TUIC 前置代理时连不通：设置全局前置代理后，
  普通节点会并入链式配置改由 sing-box 运行，而 sing-box 侧的配置生成漏写了
  REALITY，公钥与 short_id 被静默丢弃、退化成普通 TLS 握手。该配置在语法上
  完全合法（`sing-box check` 通过），只在运行时报 `unknown version: 72`
- 修复大量节点时界面打不开、按钮一直转圈无响应：
  - 端口预留改为惰性记账。此前为每个未启动节点常驻一个 TCP 监听来「占住」端口，
    上千节点即上千个套接字，启动阶段耗尽句柄并长时间持有全局锁
  - Windows 上获取进程名不再 fork `tasklist`。该命令依赖 RPC，在部分机器上会卡到
    超时（实测单次 303 秒后报错返回空），足以让启动流程僵住；改用 Win32 进程快照，
    耗时降至约 10 毫秒
  - 端口占用查询改为一次取回全表并短时缓存，批量启动 N 个节点的 `netstat` /
    `lsof` 调用从 N 次降到约 1 次
- 修复 Windows 端口匹配误判：此前用后缀匹配，`:110808` 会被误认为 `:10808`；
  同时正确处理 IPv6 的 `[::]:port` 写法
- 修复 Linux / macOS 上 `lsof` 因部分文件无权限访问而退出码非 0 时，
  整张端口占用表被丢弃、导致所有端口被误判为未占用

**新增**

- 内存容量保护：每个节点是一个独立内核进程，实测常驻约 33 MB，上千节点会超出
  物理内存导致进程被系统终止（表现为闪退）。现在批量启动前按可用内存估算容量，
  超出时明确提示「最多可启动约 N 个」而不是让机器被打崩。
  崩溃恢复路径同样受保护：此前崩溃前启用了多少节点、重启就会全部自动拉起，
  于是一开就再崩、陷入打不开的循环
- 自动启动改为后台执行，窗口不再等待节点全部拉起才显示。此前 Wails 要等
  `ServiceStartup` 返回才创建窗口，节点一多就只能看到进程、看不到界面
- 节点列表新增别名、协议、服务器地址、服务器端口、本地端口、真实 IP 六列排序，
  文本列按拼音排序且「节点2 / 节点10」按数值大小排（此前排序只支持数值列，
  文本列相减得到 NaN、结果随机）
- 列宽支持拖动调整并记忆，列设置里的「重置」会一并清空自定义列宽
- 批量启动时失败节点的提示合并为一条汇总，此前每个失败节点各弹一条会刷屏；
  同时对节点列表的整表刷新做了合并，几百次连续事件只重载一次
- 启动后的连通性验证期间单独显示「验证中」状态（琥珀色呼吸圆点）。
  此前这段时间显示为「运行中」，用户会以为节点已可用，
  而它可能几秒后就被判定不通并自动停用。运行中计数不再包含验证中的节点，
  底部另计「验证中 N 个」
- 批量启动后的可用性检测大幅提速：并发从 16 提到 64，
  新增独立的建连超时（4 秒），连不通的节点几秒即可判定，
  而已连上、只是响应慢的节点仍有完整时间读完响应
- 出口 IP 探测改用 CDN 静态资源（HEAD 请求 + `x-response-cinfo` 响应头）。
  公共 IP 查询 API 在上千节点同时探测时会限流，把可用节点误判为不通——
  实测同一批 1477 个节点，可用数曾在 1426 / 970 / 1255 之间大幅波动。
  其余查询服务作为兜底，按端口错开起始位置分摊压力
- 修复操作列「删除」按钮被截成省略号：五个按钮共需约 235px，
  而列宽固定在 206px；同时取消该列的文本截断样式（那是给文本列用的）

## 使用说明

### HTTP API

程序启动后默认监听 `127.0.0.1:9090`，API 前缀为 `/api/v1`。监听地址、端口、服务开关和 Bearer Token 鉴权可在程序的“设置 → HTTP API”中配置，保存后立即生效。监听非本机地址时必须启用鉴权。

Swagger UI 文档地址为 `http://127.0.0.1:9090/api/docs/`，OpenAPI 规范地址为 `http://127.0.0.1:9090/api/openapi.yaml`。Swagger UI 的 “Authorize” 按钮可填写设置中的 Token。

> Swagger UI 页面资源由 `unpkg.com` 加载；无法访问该 CDN 时仍可直接下载内置的 OpenAPI YAML。Token 会保存在程序目录的配置文件中，请限制该文件的访问权限，不要将 Token 提交到版本库。

开启鉴权后的请求示例：

```bash
curl -H "Authorization: Bearer YOUR_TOKEN" http://127.0.0.1:9090/api/v1/local-proxies/enabled
```

本地代理接口返回同一混合端口的 HTTP 与 SOCKS5 地址，并通过 `type` 区分 `rule`、`loadBalancer` 和 `chainProxy`。全部接口也会返回尚未启动的资源配置；需要可立即使用的代理时，请调用对应的 `/enabled` 接口。

#### 批量出口轮换（爬虫等场景）

节点采用分片运行，上千个节点也只占几个进程、约几百 MB 内存，因此可以一次全部启动，
再由客户端在这些本地端口之间轮换，每个端口对应一个独立出口 IP。

不想写代码调接口时，可直接在界面上「更多 → 复制本地代理 (HTTP / SOCKS5)」，
把地址按行复制到剪贴板（选中了节点就复制选中的，没选中则复制全部已启用节点）：

```
http://127.0.0.1:11000
http://127.0.0.1:11001
http://127.0.0.1:11002
```

也可以调接口自动获取：

```python
import itertools, requests

# 取出全部已启动节点的本地代理地址
proxies = requests.get(
    "http://127.0.0.1:9090/api/v1/local-proxies/enabled",
    headers={"Authorization": "Bearer YOUR_TOKEN"},
).json()["data"]

pool = itertools.cycle([p["httpUrl"] for p in proxies])

for url in urls:
    proxy = next(pool)          # 每个请求换一个出口 IP
    requests.get(url, proxies={"http": proxy, "https": proxy})
```

返回的每项形如 `{"id": ..., "type": "rule", "alias": ..., "localPort": 11000,
"httpUrl": "http://127.0.0.1:11000", "socks5Url": "socks5://127.0.0.1:11000", ...}`。

先用 `POST /api/v1/nodes/start` 批量启动（Body 为 `{"ids": [...]}`），
再调 `/local-proxies/enabled` 取实际可用的那批——启动失败或连不通的节点会被自动停用，
不会出现在结果里。

> 批量启动后有一段连通性验证期（界面上显示为「验证中」）。这期间节点已启动、
> 端口可用，因此也会出现在 `/local-proxies/enabled` 里，但其中一部分随后会被
> 判定不通并自动停用。要拿到确定可用的那批，可等界面上「验证中」归零后再取，
> 或调 `GET /api/v1/nodes` 按 `verifying` 字段过滤。

主要接口：

| 方法 | 路径 | 功能 |
|------|------|------|
| GET / POST | `/api/v1/nodes` | 获取 / 创建节点 |
| GET / PUT / DELETE | `/api/v1/nodes/{id}` | 获取 / 修改 / 删除节点 |
| POST | `/api/v1/nodes/{id}/start`、`/stop` | 启动 / 停止节点 |
| POST | `/api/v1/nodes/start`、`/stop`、`/delete` | 批量启停 / 删除，Body 为 `{"ids":["rule_id"]}` |
| GET | `/api/v1/local-proxies` | 获取全部普通节点、故障转移和链式代理的本地地址 |

#### 动态会话代理接口

创建时的字段说明（省略的字段取默认值）：

```bash
curl -X POST http://127.0.0.1:9090/api/v1/session-relays \
  -H "Authorization: Bearer YOUR_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{
    "alias": "住宅代理-美国",
    "localPort": 19100,
    "upstreamAddr": "gw.dataimpulse.com:823",
    "usernameTemplate": "login__cr.us;sessid.{session}",
    "upstreamPassword": "上游密码",
    "localPassword": "",
    "preProxyNodeId": "",
    "groupId": ""
  }'
```

| 字段 | 说明 |
|------|------|
| `localPort` | 混合端口，HTTP 与 SOCKS5 客户端均可接入；填 `0` 或省略则自动分配 |
| `upstreamAddr` | 上游住宅网关，必须是 `host:port` |
| `usernameTemplate` | 含 `{session}` 占位符；**留空表示原样透传**客户端传入的完整用户名 |
| `upstreamPassword` | 上游固定密码，保存在本机，客户端无需知道 |
| `localPassword` | 客户端需提供的密码，留空则不校验（仅监听本机时可留空） |
| `preProxyNodeId` | 留空 = 直连上游；`__global__` = 跟随全局前置代理；也可填具体节点 / 链式 / 故障转移的 ID |

创建后处于停止状态，需再调用 `/start`。`GET` 返回中的 `activeConns`、`totalConns`、`sessionCount` 为实时统计，仅在运行时有值。

注意：前置加速节点必须**已经启动**，中继只做转发、不会代为拉起内核进程；未启动时 `/start` 会失败并在 `lastError` 中说明原因。

### 添加代理规则

1. 点击 **"添加规则"** 按钮
2. 填写基本信息（别名、本地代理类型和端口）
3. 选择协议类型并填写服务器信息
4. 根据需要配置传输层和 TLS

### 链式代理

1. 点击 **"添加链式代理"**
2. 从可用节点中添加节点（支持搜索框快速筛选），拖拽调整顺序
3. 流量方向：第 1 个 → 第 2 个 → ... → 落地

### 故障转移

1. 点击 **"添加故障转移"**
2. 选择参与的子节点（支持搜索框快速筛选），启动后默认走第一个节点，故障时切换到后续备用节点

### 动态会话代理

适用于住宅代理服务商把会话标识编码在用户名里的场景（如 DataImpulse 的 `sessid`），
一个端口即可对应任意数量的出口 IP。

1. 点击 **"添加会话代理"**
2. 填写上游网关地址（如 `gw.dataimpulse.com:823`）和上游密码
3. 填写用户名模板，其中 `{session}` 会被替换为客户端传入的会话标识：
   `login__cr.au;sessid.{session}`（留空则原样透传客户端用户名）
4. 需要加速时选择一个**已启动**的前置节点，中继会经它连上游网关
5. 启动后按会话标识访问，换用户名即换出口 IP：

```bash
# HTTP 客户端
curl -x "http://123:x@127.0.0.1:端口" https://api.ipify.org
curl -x "http://45:x@127.0.0.1:端口"  https://api.ipify.org   # 另一个出口 IP

# SOCKS5 客户端（用 socks5h 让域名交由远端解析）
curl -x "socks5h://123:x@127.0.0.1:端口" https://api.ipify.org
```

说明：

- SOCKS5 客户端必须启用用户名认证，否则无法携带会话标识（未设客户端密码时密码可任意填）
- 出口 IP 由客户端用户名决定，因此这类节点不提供测速与健康检测
- 上游只支持 TCP CONNECT，SOCKS5 的 BIND / UDP ASSOCIATE 会被拒绝

### 测速与健康检测

- 单个节点：点击节点行的 **"测速"** / **"检测"** 按钮
- 批量：多选后点击工具栏 **"健康检测"**（未选中时检测全部）；测速在 **"更多"** 下拉里
- 故障转移 / 链式代理需先启动，测速与检测通过其本地代理端口进行

**按健康状态筛选与选中**

- 工具栏「健康」一行可按 全部 / 健康 / 失败 / 未检测 筛选，按钮上显示各类数量
- **双击**某个分类按钮即可选中该类节点，接着可批量启停或删除
- 「健康」含在线与延迟较高（链路可通）；「未检测」含尚未检测、检测中，
  以及「仅 IPv6」——本机没有 IPv6 出口时无法直接探测这类节点，
  它们不会被「选中失败」命中，避免批量删除时误删可用节点

### 批量编辑

1. 多选普通节点后点击工具栏 **"批量编辑"**
2. 每个节点一张可折叠卡片，改完后点 **"全部保存"** 统一提交

### 系统代理

- 点击节点行的 **"代理"** 按钮设为系统代理
- 点击顶部 **"取消系统代理"** 按钮取消
- Linux 下需按提示手动设置 `http_proxy` / `https_proxy` 环境变量

### 导入 / 导出

- 导出：选择节点后点击 **"导出规则"**，仅导出选中节点及其关联的分组、故障转移、链式代理（可选是否包含订阅）
- 导入：点击 **"导入规则"**，选择 JSON 配置文件
